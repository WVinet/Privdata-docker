## 1. Fix de acceso inicial

**Problema:** El hash BCrypt en el SQL seed no correspondía a la contraseña "123456", causando `Credenciales inválidas`.

**Causa raíz:** El hash `$2a$10$N9qo8uLOickgx2ZMRZoMy...` era para la palabra "password", no "123456".

**Solución:**
- Se generó hash correcto con Python bcrypt
- Se actualizó `Auth-service/docker/init/01-auth-schema.sql`
- Se recreó el volumen `postgres_auth_data` para aplicar el cambio

### Admin seeding con DataInitializer
**Problema resuelto:** El hash BCrypt en SQL era frágil y podía romperse.

**Solución:** `DataInitializer.java` ahora crea el SUPER_ADMIN al arrancar Spring Boot usando `PasswordEncoder` automáticamente. El SQL ya no tiene usuarios.

**Archivos:**
| Archivo | Descripción |
|---|---|
| `config/AdminProperties.java` | Nuevo — lee config con `@ConfigurationProperties(prefix="admin")` |
| `config/DataInitializer.java` | Extendido con `seedSuperAdmin()` |
| `resources/application.properties` | Agregadas propiedades `admin.*` |
| `docker/init/01-auth-schema.sql` | Eliminados INSERTs de usuarios |
